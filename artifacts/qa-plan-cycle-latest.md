## 2. 测试数据隔离与入口约定

每个通知测试场景使用新的 `scenario`，避免不同场景的 localStorage 串扰。不得清空整个 localStorage；如需重新跑同一场景，只删除精确键 `bula-notification-v2:<scenario>`。

建议实现并在 README 记录下列仅原型/QA 使用的稳定入口：

| 参数或控件 | 用途 | 约束 |
| --- | --- | --- |
| `mock=success\|error\|timeout` | 签到模拟结果 | 继续沿用现有行为 |
| `scenario=<unique>` | 隔离通知持久化 | 不影响签到内存初态 |
| `notificationSeed=default\|granted\|granted-off\|denied` | 通知初态 | 仅无已存记录时生效 |
| `permissionResult=granted\|denied` | 模拟通知授权结果 | 禁止调用真实通知 API |
| `systemPermission=denied` | 模拟系统撤销权限 | 保留已领取/已记账历史 |
| `prototypeDate=next` 或等价按钮 | 模拟“进入下一自然日” | 必须由已完成第 7 天状态触发；不得用 reload 冒充 |

若采用页面内开发按钮，需提供 `aria-label="模拟进入下一自然日"`，并标注“仅原型测试”。若继续使用 URL 参数，应让它表达一个可维护的日期状态，而不是通过页面刷新后的普通初态碰巧得到 day 1。

## 4. 可访问性与反馈检查

- 签到、开关、时间整行、奖励卡、任务按钮、余额入口、sheet 取消/保存和模拟下一自然日入口均有准确 `aria-label` 或可见名称。
- `role="switch"` 的 `aria-checked` 与视觉状态一致；保存时间不改变该值。
- 所有触控热区至少44×44px；不能用扩大后的透明热区覆盖相邻开关/时间按钮。
- 异步处理中使用 disabled 或同步 ref 双重防重；状态文案应可由 `aria-live` 感知。
- Modal/sheet 使用 `role="dialog"` 与 `aria-modal="true"`，关闭后焦点回到触发元素（若当前组件未实现焦点恢复，至少列为 P1）。
- 按压反馈不能改变布局；`prefers-reduced-motion: reduce` 下取消位移/缩放但仍保留状态替换。
- 禁用任务文字/勾选与背景对比足够，不能仅靠浅灰表达已领取。

## 5. 横向溢出与视觉检查

在 375×812 与 390×844 各执行一次：

1. 记录 `document.documentElement.scrollWidth <= document.documentElement.clientWidth` 与 `document.body.scrollWidth <= document.body.clientWidth`。
2. 从页面最上方滚到任务区底部，确认整页不能左右平移；奖励区自身可横滑不算页面溢出。
3. 默认第2～7天和最左第1～6天各截图一次；检查六张卡完整、轨道提示方向正确、进度节点对齐。
4. 检查提醒区斜切边缘：开关、状态文字、时间行与箭头不贴边、不遮挡、不截断。
5. 检查任务长文案在375px不覆盖按钮；允许自然换行但不能截字。
6. 检查控制台无 React warning、应用 error 和资源404；现有 PNG 素材路径不变且无拉伸。

视觉修正最多两轮：第一轮只修半卡、整页溢出、轨道错位、热区覆盖和截断等 P0；第二轮修渐隐强度、提示位置、禁用态对比和间距等 P1。两轮后剩余非阻断差异进入 known differences，不再无限调整。
