# Visual Risks & QA Priorities

## 优先风险队列

| 等级 | 风险 | 参考信号 | 建议约束/修正方式 |
| --- | --- | --- | --- |
| P0 | 页面被当成桌面网站拉宽 | 截图为 390×844 设备比例，卡片左右边距仅约 16 px | 根容器 100% 但有手机宽度上限；桌面居中，禁止将两张卡片改为左右列 |
| P0 | 签到卡右上角做成普通矩形 header | 参考图有从约 `(568,527)` 到 `(638,623)` 的斜切界面 | 用伪元素/clip-path + 局部圆角复刻；与下方主体的右上圆角分开处理 |
| P0 | IP 角色遮挡层级反了 | 角色底部 y≈219 CSS，卡片顶 y≈213 CSS | 角色 `z-index` 低于签到卡，让卡片遮住角色底部约 5–6 px；不要把整个角色放在卡片前 |
| P0 | 6 个奖励格在 320 px 下溢出/重叠 | 390 基准总宽约 321 px，固定尺寸无法原样塞入 288 px 内宽 | 使用 6 列 minmax grid，奖励格与 gap 等比缩小；硬币使用 `object-fit:contain` |
| P0 | 奖励格、节点、日期三者中心不一致 | 参考中 6 个中心约为 `x=139,273,406,539,673,807` | 三层共用一套 grid columns；进度线两端停在首尾节点中心，不到卡片边缘 |
| P0 | 只渲染 4 个任务导致 844 px 截图底部留白 | 参考底部已露出第 5 行的顶部 | 列表至少提供第 5 行模拟内容，使其在 844 px viewport 处被自然截断 |
| P1 | 顶部背景用单一 pink 或普通两色线性渐变 | 左上为暖黄，中右上为珊瑚粉，左侧在 y=450 仍偏黄 | 叠加至少两层 radial gradients，再对下部淡出至 `#F9F8F6` |
| P1 | 标题和数字的酒红过渡被忽略或滥用 | `434`、“已连续...”、“每日任务”左端有酒红感，右端为黑 | 只在参考明确的 3 处用短距离水平渐变文字；其他标题保持纯黑 |
| P1 | 卡片圆角按用户笼统的 20–28 px 全部放大 | 像素几何显示大卡主圆角更接近 14–17 CSS px | 以截图实际边界为先，大卡从 16 px 起调；奖励格从 8 px 起调，CTA 保持胶囊 |
| P1 | 任务行文字在 320/375 下被状态按钮挤压 | 中间描述最长 13 个中文/数字，右按钮约 63 px | 中列 `min-width:0`，描述 nowrap + 合理字号 clamp，按钮 `flex-shrink:0` |
| P1 | CTA 渐变方向/色相错误 | 上部约 `#FF407F`，底部约 `#FF786F` | 使用垂直渐变，不使用 Tailwind 默认紫粉，不加蓝紫色偏 |
| P1 | 开关或 CTA 点击后布局跳动 | 签到前后文案长度不同 | 按钮宽高固定；连续天数数字 span 保持行高；节点状态只改色不改尺寸 |
| P1 | Modal/toast 在桌面上相对整屏定位 | 页面是居中手机容器 | overlay 相对 AppShell 定位，只覆盖手机页面宽度 |
| P2 | 位图被拉伸 | 角色和硬币都有可见圆形/软体比例 | 所有 PNG 使用明确宽高槽位 + `object-fit:contain` |
| P2 | 每个硬币用不同位图导致尺寸漂移 | 截图中粉/灰币的直径一致 | 只使用 `coin-pink.png` 和同构的 `coin-gray.png`，所有位置复用同一图片组件 |
| P2 | 手机状态栏图标风格混乱 | 截图为统一黑色 iOS 实心 glyph | 用一套 SVG/CSS geometry，统一高度和光学居中；不用 emoji |

## 320 / 375 / 390 / 430 检查矩阵

| 宽度 | 主要检查 | 预期 |
| --- | --- | --- |
| 320 | 6 列奖励、“第二天”等不换行；任务描述不插入右按钮；CTA 不压扁 | 无水平滚动，可接受等比缩小小格和间隔 |
| 375 | 对照表中 375 CSS 坐标；页边距约 16 px，卡片宽约 343 px | 比 390 基准等比小 3.85% |
| 390 | 主视觉验收尺寸；截图高 844 px 时第 5 行部分可见 | 与 946×2048 参考图轮廓位置最接近 |
| 430 | 页面是否继续放大或在手机上限内居中；角色不冲出右边 | 建议不高于 430；若追求严格截图尺寸，可在 390 之上居中保持不放大 |

## 不可用视觉差异掩盖的功能问题

- 返回、规则、开关、签到、全部任务、去开启、去邀请必须有反馈；“已领取”必须是 disabled。
- 点击签到后，文字变为“今日已签到”、对应节点更新、连续天数增加，toast 文案为“签到成功 +1 布拉币”。
- Modal 不得导致背景页面宽度因滚动条变化而跳动。

## 验收顺序

1. 390×844 实浏截图与参考左右对照/叠加，先修正卡片 y 位置和总宽。
2. 固定 6 个奖励中心、进度线和 CTA 尺寸。
3. 调整 IP 角色槽位及遮挡。
4. 调整字号/字重、粉色/灰色对比，最后调抗锯齿级别的 1 px 差异。
5. 再在 375、320、430 检查无溢出和无重叠，不用窄屏适配反向改坏 390 主基准。
